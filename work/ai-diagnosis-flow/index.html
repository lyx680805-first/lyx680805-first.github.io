01 / THE PRODUCT DECISION

复杂业务的问题，
通常不是“不会做”，而是不知道先做什么。

通用AI可以很快生成一段回答，但它不会自动知道用户现在处在哪个阶段、哪条证据还缺、哪一步完成后才值得继续。

我把长期交付中的判断模式拆出来，写成输入门槛、阶段路由、问题合同、输出合同与状态写回。系统的价值因此从“会回答”变成“会推进”。

FROM SURFACE QUESTION
表面表达

“帮我想个定位。”

看起来像内容生成任务，实际上可能还没有明确人群、场景或付费证据。

→
真正要判断的

“你现在缺的是一句话，还是一条能被验证的价值选择？”

先定位决策阶段，再决定追问什么、调用哪条工作流、交付什么下一步。

02 / SYSTEM SURFACE

七个工作台，
不是七个菜单。

它们是一条从判断到执行、再回到判断的业务链。每个工作台都有自己的输入、产出与下一步，不把所有问题都交给同一个聊天框。

01IP诊断先判断处在哪个阶段
02定位梳理把价值选择说清楚
03产品打造把承诺变成交付
04内容获客让内容承担验证任务
05营销转化拆开信任与行动阻力
06资料管理让经验成为可调用资产
07复盘优化把结果写回下一轮

04 / FAILURE → MECHANISM

真正让我学到东西的，
不是一次顺利运行。

有一次，诊断已经完成，但点击“继续”没有反应。问题不在文案，而在历史状态与当前步骤身份不一致：页面看到了结果，服务端却无法确认下一步该接哪条任务。

SYMPTOM“继续”没有反应用户停在完成页
→
ROOT CAUSE状态与步骤身份不一致结果存在，但无法恢复
→
PRODUCT CHANGE版本映射 + 状态恢复 + 预发布复现把失败写进机制，而不是只补一个按钮

05 / OUTPUT CONTRACT

一次好的诊断，最后只交付三件事。

01阶段判断

你现在处在什么阶段，为什么。

02关键缺口

哪条证据不足，补它会改变什么决定。

03下一步行动

未来7天只做什么，完成标准是什么。
